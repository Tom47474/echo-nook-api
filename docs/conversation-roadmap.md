# 对话功能开发规划与进度

更新时间：2026-11-25

本文记录 EchoNook 前后端对话功能的后续实施顺序、验收要求和进度。以各阶段和任务的实际状态为准；部分基础设施准备完成不代表对应业务功能已经实现。

## 当前基础

- 前端通过 `fetch` 消费带内部窗口 ID 的服务端 SSE；页面只显示当前身份的一个持续对话窗口，支持停止、清空和消息恢复。
- 服务端通过统一模型接口支持演示回复和 OpenAI 兼容模型调用。
- 新会话流式接口已绑定会话 ID，保存完整用户/助手回合并从数据库加载最多 20 条历史；S4-1 已加入估算 token 预算，当前前端已接入，旧接口仅保留兼容。
- 生成失败时前端保留已收到的助手内容并标记失败；失败或取消的部分回复会带内部中断标记进入后续上下文。
- 开发或测试部署可显式开启对话调试浮动球；正式环境由服务端渲染门禁强制关闭。

## 进度维护规则

1. 按以下阶段推进；开始任务时将状态改为“进行中”，通过验收后再改为“已完成”。状态使用：未开始、进行中、已完成、受阻。
2. 每完成一个任务，立即更新本文对应任务状态和实施记录，写明完成日期、实际行为、代码路径、验证方式与结果、遗留问题。涉及前端的任务也在本文追踪。
3. 部分实现或尚未验证不能标记完成；受阻时记录原因、依赖和下一步。
4. 每完成一个任务，同步更新 [技术难点与解决方案](conversation-technical-decisions.md)，严格遵循该文档“后续任务的写作标准”：用具体场景、逐步流程、关键代码原因、失败/并发处理、验证和边界详细解释前后端实现，不能只写概括句；接口、数据结构、配置或运行方式变化时，还要更新 `docs/backend-architecture.md`、`README.md`，涉及前端时同步更新前端文档。规划不能替代当前实现说明。
5. 顺序或范围调整时记录原因及依赖，保留可追溯的变更记录。本文不得包含密钥或真实用户对话内容。
6. 核心函数、方法、外部调用接口及关键事务、并发和资源释放逻辑使用中文注释说明目的与边界；注释解释原因，不重复代码表面行为。
7. 每完成一个任务并通过对应验证后，将该任务的代码、测试和文档提交为 Git commit；前后端是独立仓库，涉及两个仓库时分别提交，并在交付说明中列出 commit。不要把未完成的下一任务混入本次提交。

实现建议：前端独立调试模块，通过受控调试适配层驱动对话状态和 ReplyProvider，避免在每个业务组件中散布测试分支。先在浏览器端模拟故障；确需服务端故障注入时，后端必须单独校验环境和开关，正式环境不注册调试接口。测试身份鉴权与数据归属仍属于上线前门槛。

环境标识与 Git 分支各司其职：分支管理代码，环境配置决定运行行为。前后端均创建本地 `test` 分支用于测试集成；不能依靠分支名决定调试入口可见性。生产部署应显式关闭调试能力，环境与部署检查从本阶段建立，并在阶段五复核。

阶段二当时接口（目前仅作旧版兼容，页面不再调用列表/新建/切换/删除）：

```text
POST   /api/v1/conversations
GET    /api/v1/conversations
GET    /api/v1/conversations/{id}/messages
POST   /api/v1/conversations/{id}/messages:stream
DELETE /api/v1/conversations/{id}
```

当前流程：提交会话 ID 和当前问题 → 原子创建用户/助手消息 → 查询数据库历史 → 构造模型上下文 → 流式返回并按检查点保存草稿 → 保存助手最终状态。

当前由 `app/db/` 管理连接与迁移设施，`app/conversations/` 管理模型、查询、流式业务和持久化状态；路由、业务逻辑、数据库和模型供应商适配保持分离。

### 阶段五身份与用量归属方案

S5-1 已实现游客与账号身份：服务端签发随机 Cookie 并在数据库保存其哈希；账号采用用户名和密码登录，密码以 scrypt 加盐哈希保存。浏览器不得自行指定 `owner_id`。登录账号也使用同一套对话能力。游客会话仅凭该浏览器仍持有的有效凭证恢复；清除凭证后不能靠会话链接认领。跨设备恢复属于登录态能力。游客与登录账号的限额可以不同，具体阈值在 S5-2 确定；界面不展示 token 用量。

2026-11-25 单窗口需求调整：游客登录后直接显示账号窗口，游客消息保留在原游客身份；退出后凭本浏览器的游客 Cookie 恢复游客窗口。注册、登录和退出都不导入或复制消息，旧导入接口已移除。每个身份只有一个当前窗口；清空仅删除当前窗口消息和摘要，保留内部调用记录。旧版同一身份多个会话在 `0006` 迁移中按时间合并；没有归属的旧数据仍需开发环境显式认领。

会话归属和历史用量归属是两个维度：登录前的真实模型调用归游客，登录后的新调用归账号；身份切换或清空**不追扣**其他身份额度，也不改写历史调用的归属。S5-1 已为新 `model_calls` 保存调用开始时的身份/用量归属快照；此前历史记录的快照为空，不能可靠倒推。`summary` 与 `reply` 分别归属，供应商未返回的 token 保持未知，不能按 0 计。该用量仅供服务端成本、限额和故障排查，不提供前端用量展示。

S5-2 默认配置 `CONVERSATION_LIMIT_ENABLED=false`，方便本地开发不限额；设置为 `true` 后，游客/账号分别使用 `.env` 的日回复数和每分钟请求数。日额度按 UTC 自然日读取持久化的主回复调用，因此清空消息和身份切换不能重置；摘要不占发送次数。分钟频率、同身份生成、全局并发和登录失败窗口当前是单进程状态，生产部署必须先保持单工作进程，多实例共享限额属于后续部署扩展。连接、读取和模型总超时不受总开关影响。下一步为 S5-3 结构化日志。

S5-2 每个环境变量的单位、启用条件、错误码、示例配置和“次数额度不等于供应商 Token/余额”的边界统一维护在[对话额度、频率、并发与模型超时配置](conversation-limits.md)，部署或调整额度前应先阅读该文档。
